CLOSE THE GAP

Claude + Jira + Confluence — your hands-on technical evidence

This is the direct answer to your own flagged development area — "mostly planning and governance, not executing." Below is the concrete, technical architecture behind what you're actually building at FXCM: an agentic workflow from user story to test script to code, not just a training rollout. Note upfront: AIA's own public tech stack is Microsoft-centric (Azure, Dynamics 365, Copilot) rather than Jira/Confluence — so present this as evidence of your own hands-on pattern, not a claim about what AIA runs on.

Connect Claude to the ticket and knowledge system

Claude connects to Jira and Confluence via the Model Context Protocol (MCP) — the standard mechanism modern AI assistants use to read and write in external tools, once authorised. In practice, the first real step is governance, not wiring: agree scope with IT/Security — read-only access first, write access only after a trial period — with Jira/Confluence's own history serving as a natural audit trail.

User story generation from a Confluence brief

Feed Claude an existing product brief or epic page from Confluence, with a prompt pattern like: "Draft 3–5 user stories in 'As a [role], I want [capability], so that [benefit]' format, each with Given/When/Then acceptance criteria, based on this brief." A human Product Owner reviews and edits the draft; once approved, the stories go into Jira — either pasted in manually, or, with write access via the MCP connector, created directly by Claude and tagged to the right sprint or epic.

This turns a blank-ticket problem into a review problem — the Product Owner's time shifts from writing to judging, which is a faster and arguably higher-value use of their attention.

Automated test script generation from the approved acceptance criteria

Once a story's acceptance criteria are signed off, feed them back to Claude to generate either Gherkin/BDD scenarios for manual QA, or actual automated test code (for example, in Playwright or Cypress) matching each criterion directly. The output attaches to the Jira ticket or pushes to the test repository; QA reviews and adjusts before anything merges.

Ticket-to-code with Claude Code

Claude Code — Anthropic's agentic coding tool — connects to the same Jira ticket via MCP, reads the description, the acceptance criteria, and any linked Confluence design doc, and drafts a first-pass code change or pull request against the relevant repository. The developer reviews and iterates with it interactively before merging; Claude Code can also post a summary comment back onto the Jira ticket linking the PR, closing the loop from ticket to shipped code without manual copy-paste between systems.

The governance wrapper — this is literally your current job

None of the above runs unsupervised: a RACI for who approves AI-drafted stories, tests and code before anything is actioned, a mandatory human review gate before merge or publish, and the tools' own history as an audit trail. This is the exact governance-first framework you're already designing at FXCM for enterprise Claude adoption — the same discipline, just described here against a concrete technical workflow instead of in the abstract.

HOW TO SAY THIS IN THE ROOM

Be precise about what's built versus what's designed

"At FXCM, I'm designing the governance and workflow for exactly this pattern — Claude connected into our own tooling to draft user stories and support test creation, with human review as the gate before anything ships. I haven't personally built the ticket-to-code step with Claude Code yet, but I understand the architecture well enough to know what it would take, and where the governance risk sits — which is the piece that actually matters for a change management role, not the engineering itself."

This is a genuinely strong answer precisely because it doesn't overclaim: it shows real architectural understanding while being accurate about which parts are live versus designed, which is exactly the credibility a data-and-delivery-literate interviewer like Simon Lee will be listening for.
